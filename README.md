# מערכת גיוס מועמדים (HR Recruitment System)

מערכת גיוס לחברת HB Consulting: קליטת מועמדים ממייל ומקבצים, ניתוח קורות חיים
ב-AI, ניהול התהליך מול לקוחות, ודירוג מועמדים מהמאגר מול בקשות גיוס.

המבנה נגזר מצ'קליסט הגיוסים של מנהלת משאבי האנוש — שלושת משטחי העבודה שלה
(דשבורד, משרות לגיוס, מועמדים) קיימים במערכת באותן עמודות ובאותה שפה.

## מבנה

- **`backend/`** — Node.js + Express + TypeScript + PostgreSQL, אימות JWT.
- **`frontend/`** — עמוד יחיד (HTML/JS, ללא build) שמדבר עם ה-API.

## מודל התהליך — חשוב להבין לפני שמשנים קוד

מועמד **אינו** נמצא בשלב אחד. התהליך האמיתי עוקב אחרי ארבעה סימונים **עצמאיים**,
כי מועמד יכול להיות מרואיין ולקבל משימה בלי שהקו"ח שלו הועבר ללקוח:

| סימון | עמודה |
|---|---|
| ראיון TEAMS | `interviewed_teams` |
| קיבל משימה (רק במסלול רב-תחומי) | `got_task` |
| הועבר ללקוח | `sent_to_client` |
| אושר ע"י הלקוח | `client_approved` |

בנוסף יש **סטטוס תוצאה** נפרד (`outcome_status`) באוצר המילים של המגייסת:
`צ"ש גבוהות`, `בברור`, `הסיר/ה מועמדות`, `נפסל איזור ג"ג`, `אין מענה`, ועוד.
`stage` נשאר לצורך הלוח הקנבן בלבד.

בקשת גיוס (`jobs`) עוברת `awaiting → filled / not_filled / frozen`, ונושאת את
מטריצת הדרישות המקצועיות (`requirements`, JSONB) שכל פריט בה מסומן חובה/יתרון.

## יכולות

- **סריקת מייל** (Gmail + Outlook דרך OAuth) — מושכת מועמדים ומצרפי קו"ח.
- **ניתוח קו"ח ב-Gemini** — סיכום, חוזקות, נקודות לבירור, שאלות לראיון, הכשרות,
  גיל, מיקום, ותחום עיסוק. מחלץ גם שם/מייל/טלפון מתוך הקובץ.
- **ייבוא מרובה של קבצי קו"ח** — עשרות קבצים בבת אחת (למשל יצוא צ'אט וואטסאפ),
  כולל `.doc` ישן. כל קובץ נוצר, מנותח, ומשויך אוטומטית למשרה המתאימה ביותר.
- **ייבוא מצ'קליסט הגיוסים** — קריאת קובץ ה-`.xlsx` שלה ישירות בדפדפן. מייבא
  מועמדים **ללא קורות חיים**, לפי הפילוח שבאקסל.
- **התאמה הפוכה** (`POST /api/jobs/:id/match`) — בהינתן בקשת גיוס, דירוג המאגר
  הקיים מולה. משקלל את מטריצת הדרישות ואת תיאור המשרה החופשי, ומציף גיאוגרפיה
  וציפיות שכר מעל התקציב — שתי הסיבות שבפועל פוסלות מועמדים.
- **דשבורד** — 14 המדדים שלה + גרפים, וכל מספר לחיץ לרשימת הרשומות שמאחוריו.
- **טיפול בכפילויות** — איחוד תצוגתי לפי שם/מייל/טלפון, ותיקון שמות מתוך הניתוח.

## הרצה מקומית

### Backend
```bash
cd backend
cp .env.example .env          # ערוך: DATABASE_URL, JWT_SECRET, GEMINI_API_KEY
npm install
npm run migrate               # מיגרציות forward-only מתוך src/db/migrations
npm run reset-admin -- admin <סיסמה>
npm run dev                   # פורט 3001
```

### Frontend
עדכן את `frontend/config.js` כך ש-`window.API_BASE` יצביע ל-backend, והגש את
`frontend/` משרת סטטי (`npx serve frontend`).

## פריסה

- **Database**: Neon — PostgreSQL.
- **Backend**: Render — Web Service (Docker), Root Directory = `backend`.
  משתני סביבה: `DATABASE_URL`, `JWT_SECRET`, `FRONTEND_URL`, `GEMINI_API_KEY`.
  מיגרציות רצות אוטומטית בהפעלה, והשרת מאזין רק אחרי שהן הצליחו — כלומר
  `/health` מחזיר 200 רק אם המיגרציה עברה.
- **Frontend**: Netlify, פרויקט `hrforhb`.

### פריסת ה-Frontend — שים לב

האתר **מנותק מ-GitHub**, ופקודת `netlify deploy --prod` הרגילה מוחזרת עם
`Forbidden`. הדרך שעובדת: להעלות כדראפט ואז לפרסם אותו.

```bash
netlify sites:list                       # לאיתור ה-site id של hrforhb
netlify deploy --dir=frontend --site=<site-id>          # מחזיר deploy id
netlify api restoreSiteDeploy --data '{"site_id":"<site-id>","deploy_id":"<deploy-id>"}'
```

חשבונות: הריפו תחת `Justin8001`, ואילו Netlify תחת `yc3057@gmail.com`.
חיבור מחדש של האתר ל-GitHub יבטל את הצורך בדרך העוקפת (הריפו ציבורי, כך שמגבלת
"תורם לא מזוהה" בתוכנית החינמית כבר לא רלוונטית).

## נקודות שכדאי להכיר

- **זהות שורות בייבוא** — לאקסל אין עמודת מזהה, ולכן כל שורה מזוהה לפי מיקומה
  (`import_key`). ניסיון קודם לזהות לפי תפקיד+לקוח+תאריך איחד בקשות נפרדות: לקוח
  שמבקש שני תקנים לאותו תפקיד באותו יום הוא שתי בקשות, ובמקרה אחד משרה פתוחה
  נעלמה מאחורי מאוישת. הייבוא **מאמץ** רשומות מייבוא ישן במקום לשכפל אותן.
- **מועמדים מהאקסל אין להם קו"ח**, ולכן אין להם ניתוח AI. מנוע ההתאמה קורא במקום
  זאת את סיכום שיחת הטלפון שלה, והשוואת המונחים עמידה לכתיב ולסדר מילים
  (היא כותבת "ענפית בניה", הלקוח דרש "בנייה ענפית").
- **גיליונות האקסל מרופדים למיליון שורות** (אחד מהם 255MB של XML כשפורסים אותו).
  הקריאה בדפדפן זורמת ונעצרת כשהנתונים נגמרים — אין להחליף אותה בפרסור DOM.
- **פער ידוע מול הדשבורד שלה**: המערכת מציגה 41 שרואיינו ב-TEAMS והיא 40. הנתונים
  מכילים 41 שורות מסומנות; טווח הנוסחה שלה נעצר שורה אחת מוקדם.

## מה עוד לא נבנה

- מודעות דרושים אוטומטיות (עלה בפגישת האפיון).
- ממשק לסימון "לא לגייס שוב" — השדות קיימים במסד ומוצגת אזהרה, אבל אין מסך לסימון
  ולא יובאה רשימה מ-RealBoard.
